00-30 용어

용어정의
아웃도어 세션사용자가 레저 활동(오프로드, 차박, 캠핑·낚시 등)을 하러 간다고 승인한 기간. 리본·SOS·엽서 기능은 이 세션 안에서만 켜진다.
리본길 상태 정보. 신호색(초록·노랑·빨강)과 상태 태그, 한 줄 설명으로 이뤄진다. 시간이 지나면 흐려지고 사라진다.
SOS 도움"차가 빠졌다", "다쳤다"처럼 근처 사람의 도움을 청하는 신호. 반경 안의 세션 중인 차량에만 보인다.
SOS 주의낙석, 침수, 쓰러진 나무처럼 근처를 지나는 사람이 알아야 할 위험. 반경 안 모든 사용자에게 보인다.
엽서머문 장소에 남기는 감상. 잠긴 채 그 장소의 우체통에 들어가고, 그 장소에 가야 열린다.
우체통엽서가 모이는 장소 단위. 차박지·노지·주차 가능 지점에 생긴다. 서버의 Waypoint(지점) 문서와 같다.
현장 티켓서버가 "이 사람은 지금 이 장소에 있다"고 확인해 주는 서명된 짧은 증표(기본 120초). 쓰기와 우체통 열기에 필요하다.
머문 기록음영 지역에서 차량이 한 장소에 정차해 있던 시각·위치의 로그. 신호가 돌아오면 서버가 검증해 엽서를 사후에 열어 준다.
P단 게이트기어 P(또는 주차 브레이크 체결)일 때만 열리는 기능 묶음.

03-10 드라이버 베네핏

세 기능의 역할을 나눈다. 리본은 설치하는 이유, SOS는 켜 두는 이유, 엽서는 남에게 말하는 이유다.

역할베네핏기능지금의 대안과 차이
① 설치 이유"이 길, 지금 갈 수 있나?"에 대한 답리본동호회 카페·단톡방·블로그는 오래됐거나 위치가 흐리다. 리본은 현장 인증(150m 현장 티켓), 10일 신선도, 정확한 지점을 갖는다.
② 켜 두는 이유고립됐을 때 근처에 누가 있는지 안다SOS지금은 같은 목적으로 근처에 와 있는 차량을 알 방법이 없다. SOS 도움은 반경 안 세션 중인 차량에게만 간다(20-10).
③ 말하는 이유장소에 남는 기억, 다시 갈 이유엽서·우체통다른 지도·커뮤니티 앱에 없는 차별점. 넣어야 열리고(PUT_FIRST), 1년 뒤 졸업한다.

차량이라서 생기는 가치 (폰 MapCall과 겹치지 않는 부분)

  • 주행 중에는 받기만 한다. 리본 지점에 다가가면 TTS가 "300m 앞 진흙, 3일 전"을 읽는다. 폰을 꺼내지 않는다.
  • P단이면 쓰기가 열린다. 정차 여부는 차가 안다. 사용자가 모드를 바꾸지 않는다(30-10).
  • 세션이 스스로 제안된다. 목적지 유형, 장시간 정차, 험로 모드(확인 필요)로 아웃도어 세션을 제안한다.
  • 내 차 기준으로 판단한다. "폭 좁음" 리본을 CarInfo의 차폭과 비교해 안내한다.
CAUTION

정보가 없으면 베네핏은 0이다(콜드 스타트). 차량 앱은 폰 MapCall과 같은 아틀라스 데이터를 쓴다. MapCall 쓰기는 2026-10-25부터 모든 로그인 사용자에게 열려 있어 데이터가 쌓이기 시작했다. 다만 양은 아직 적다. 시연 지역은 리본을 미리 채워 두라(80-50).

WARNING

SOS를 "구조 수단"으로 표현하지 말라. 음영 지역에서는 보낼 수 없다(05 NO-GO). 화면·스토어 문구는 "근처 차량에 알리는 보조 수단"으로 쓰고, 119·긴급출동 안내를 항상 먼저 보여 준다.

CH 05

구동성 판정 (Pleos 플랫폼 적합성)

Pleos Playground 공식 문서(SDK 2026-10-19 릴리스)와 대조했다. REV 2 구조의 결론은 세 가지다.

GO

핵심 기능은 SDK로 구현된다. 위치·근접 알림(FusedLocation), 목적지(NaviHelper), 음성 입출력(STT·TTS), 주차 브레이크·주행 거리(Vehicle)로 리본, SOS, 엽서를 모두 만든다.

조건부

차박 중 앱 동작은 차량 전원 상태에 달렸다. 시동이 꺼진 상태에서 인포테인먼트 앱이 도는지(전기차 유틸리티 모드 등)는 문서에 없다. 확인이 필요하다.

NO-GO

신호가 없는 곳에서 SOS 전송. 차량 앱 SDK에 위성 통신이 없다. 음영 지역에서는 보낼 수 없다는 사실을 화면과 음성으로 분명히 알린다.

  2. "예"는 아틀라스 POST /ribbons/:id/confirm로 보낸다. 확인 수와 마지막 확인 시각이 신선도에 반영된다.
  3. "아니요"는 같은 지점에 초록 리본(clear)을 새로 다는 것으로 처리한다.
TASK 40-07-00-801SEQ-07 머물기·엽서 쓰기
조건 P단, 현장 티켓SDK STT
  1. P단으로 머무는 장소에서 "엽서 쓰기"를 누른다. 앱은 현장 티켓을 요청한다(POST /presence).
  2. 서버는 가까운 이름 있는 지점에 붙이거나, 없으면 그 자리의 셀을 우체통으로 만든다(20-10, 50-20 참조).
  3. 음성으로 받아쓰고 키보드로 고친다(P단). 형식: 텍스트 엽서(기본) 또는 폰에서 찍은 사진 엽서.
  4. 옵션: 1년 뒤 공개 전환 동의(아틀라스 "졸업"), 열릴 때 알림 받기.
  5. 투함하면 publishAfter가 지나야 다른 사람의 우체통에 나타난다.
WARNING

도로 위, 갓길, 차단기 안쪽, 금지 구역(70-20)에는 우체통을 만들지 마라. 차량 모드에서는 노선 위 어디나 붙는 트레일식 스팟을 쓰지 않는다.

TASK 40-08-00-801SEQ-08 우체통 열기 (현장)
API POST /waypoints/:id/mailbox/open
  1. 현장 티켓을 받는다. 위치 정확도 100m 이내, 지점 150m 이내여야 한다(아틀라스 기본값).
  2. 우체통을 연다. 서버는 반경 120m 안의 우체통을 모두 "여기"로 본다.
  3. 내 엽서가 이 근처에 없으면 열리지 않는다(PUT_FIRST). "먼저 한 통 넣어 주세요"라고 안내한다.
  4. 하루 3통이 정해진 규칙으로 골라진다. 본문을 보여 주고, "읽어주기"는 TTS로 낭독한다.
NOTE

서버는 누가 언제 어느 엽서를 열었는지 저장하지 않는다. "내 엽서가 읽혔다" 알림을 만들려면 이 원칙을 깨야 하므로 넣지 않는다.

TASK 40-09-00-801SEQ-09 음영 지역 머묾 → 사후 도착 엽서
  1. 신호가 없는 장소에서 P단 30분 이상 머물면 차량이 머문 기록(셀, 시작·끝 시각, 정확도, 주변 궤적 요약)을 암호화해 저장한다.
  2. 엽서를 쓰면 대기열에 넣는다.
  3. 신호가 돌아오면 머문 기록과 엽서를 올린다. 서버는 다음을 확인한다.
    1. 머문 셀이 우체통 반경 안인가
    2. 머문 기록 전후의 이동 속도가 차량으로 타당한가(sosMaxSpeedKmh 같은 방식, 차량값)
    3. 기록이 그 차량 세션에서 나왔는가
  4. 통과하면 엽서를 투함하고, 그 우체통의 엽서를 "도착한 엽서"로 연다: "어젯밤 머문 곳에서 엽서 3통이 도착했어요."
CAUTION

사후 검증은 실시간 확인보다 약하다. 사후 열람 엽서에는 하루 열람 수를 더 낮게 주는 등 남용 한도를 따로 둔다.

TASK 40-10-00-801SEQ-10 SOS 도움 요청
조건 세션 ON, 신호 있음API POST /sos
  1. SOS를 누르면 먼저 119와 현대차 긴급출동 연결 버튼을 크게 보여 준다. 다친 사람이 있으면 119가 우선이다.
  2. "근처 사람에게 도움 요청"을 고르면 상황을 고른다: 차가 빠짐, 고장, 배터리·연료 부족, 다침, 길 잃음.
  3. 앱이 차량 정보를 붙인다: 남은 주행 가능 거리, 차량 크기(견인 판단용). 위치 공개는 이 단계에서 다시 동의받는다.
  4. 반경 안 세션 중 차량에 알린다. 유효 시간은 아틀라스 도움 기본값(3시간, 최대 6시간)을 시작점으로 한다.
  5. 30분 전 "아직 도움이 필요하세요?"를 묻는다(아틀라스 재사용).
WARNING

SOS는 구조 기관을 대신하지 않는다. 앱 어디에도 "구조를 보장한다"는 표현을 쓰지 마라. 신호가 없어 보내지 못했으면 "보내지 못했습니다"를 화면과 음성으로 알린다.

TASK 40-11-00-801SEQ-11 SOS 응답
  1. 반경 안 세션 중 차량은 정차 시 SOS를 확인한다. 주행 중이면 음성으로 "5km 안에서 도움 요청이 있어요. 정차 후 확인하세요."만 말한다.
  2. "가는 중"을 누르면 NaviHelper로 그 위치를 목적지로 설정한다.
  3. 도착 반경(아틀라스 sosArriveM)에 들어가면 "만남" / "아무도 없음"을 고른다. 이후 흐름(투표, 확인 요청, 제재)은 아틀라스를 그대로 쓴다.
TASK 40-12-00-801SEQ-12 SOS 주의 알리기
  1. 음성 또는 P단 화면에서 위험 종류를 고른다: 낙석, 침수, 쓰러진 나무, 화재·연기, 야생동물, 폭풍(아틀라스 주의 태그).
  2. 반경 안 모든 사용자에게 보이고, 세션 중 차량에는 근접 음성 경고로 등록된다.
  3. 다른 사용자의 "아직 있음 / 사라짐" 투표로 수명이 줄거나 늘어난다(아틀라스 재사용).
TASK 40-13-00-801SEQ-13 세션 종료·공개 시작
  1. 사용자가 끝내거나, 집·회사 반경에 들어가거나, 24시간 동안 세션 신호가 없으면 끝낸다.
  2. publishAfter를 정한다: 머문 장소에서 2km 이상 벗어난 뒤 2시간(가설값). 그때부터 이 세션의 리본·엽서가 공개된다.
  3. 머문 기록은 24시간 뒤 삭제한다.
TASK 40-14-00-801SEQ-14 신고·삭제·동의 철회
  1. 모든 리본·엽서·SOS에 신고를 둔다(P단). 신고 3건이면 자동으로 숨기고 관리자 검토로 넘긴다(아틀라스 재사용).
  2. 동의를 철회하면 관련 데이터 경로를 즉시 끄고 저장 데이터를 즉시 삭제한다.
TASK 40-15-00-801SEQ-15 운전자 전환·차량 매각
  1. P단 첫 화면에서 프로필을 바꾼다. 세션과 대기열은 프로필별로 분리한다.
  2. "이 차에서 내 데이터 지우기"로 로컬 캐시·대기열·토큰을 지운다. 계정 데이터는 남는다.
